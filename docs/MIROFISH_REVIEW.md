# MiroFish-Offline 적용성 검토

> 대상: https://github.com/nikmcfly/MiroFish-Offline
> 질문: "시장반응 시뮬레이션을 통한 채점"에 직접 적용 가능한가?
> **결론: 직접 적용 부적합 (TAKE-IDEAS-ONLY). 핵심 개념만 차용해 자체 경량 구현.**

---

## 무엇인가
중국 프로젝트 MiroFish 의 영문·셀프호스팅 포크. **문서(보도자료/정책초안/PDF)를 입력**하면
엔티티를 추출해 **Neo4j 지식그래프**를 만들고, 그 엔티티에 기반한 수백 개 LLM 페르소나를
**CAMEL-AI OASIS** 프레임워크의 가상 트위터/레딧에서 구동해 **서술형 여론 시뮬레이션 보고서**를 낸다.
즉 핵심은 **에이전트 기반 소셜 시뮬레이션**이지, 설문/점수 모델이 아니다.

## 아키텍처
- 4단계 파이프라인(순차·필수): ① 문서→Neo4j 그래프 ② 그래프 엔티티에서 페르소나 생성
  ③ OASIS 소셜 시뮬레이션 ④ `report_agent.py` 서술형 보고서
- 엔진: `camel-oasis==0.2.5` / `camel-ai==0.2.78`
- 모델: **로컬 Ollama**(기본 `qwen2.5:32b` + `nomic-embed-text`), OpenAI 호환 엔드포인트
- 에이전트 수는 사용자가 못 정함 → **그래프 엔티티 수로 자동 결정**. 각 행동(post/comment/like…)이 LLM 호출.
- 입력: **문서 + graph_id 필수**(원문 텍스트 직접 실행 경로 없음) / 출력: SQLite 게시물·`actions.jsonl`·서술형 MD

## 기술/라이선스
- Python 3.11+ (Flask) + Vue/Node. deps: flask, neo4j≥5.15, camel-oasis, camel-ai, PyMuPDF, pydantic
- Docker Compose 3서비스(app + Neo4j + Ollama GPU). **권장 32GB RAM / 24GB VRAM / 50GB 디스크**
- **라이선스 AGPL-3.0**(전염성 copyleft, 네트워크 사용 조항)
- v0.2.0, 2026-03 생성·최근 갱신, ⭐~2,345 / fork 621. 단일 메인테이너, Python 3.12+ 호환 미해결.

## "Offline" 의미
외부 SaaS 없이 **로컬 Neo4j + 로컬 Ollama**로 구동(진짜 로컬 모델 실행). OpenAI 호환이라 호스팅 API로 재지정은 가능하나 기본은 무외부.

## 적용 부적합 사유 (증거 기반)
1. **입력 계약 불일치** — 짧은 구조화 아이디어(문제/타겟/기능)를 직접 못 받는다. **Neo4j 그래프가 선행 필수**.
   짧은 블러브는 엔티티가 거의 없어, 페르소나가 "타겟 시장"이 아니라 "블러브 속 단어"를 대표하게 됨
   (`oasis_profile_generator.py`: personas from entities, *"not a target market"*). 시장반응 채점과 근본 미스매치.
2. **점수 미산출** — 최종 산출물은 **서술형 프로즈, 수치 지표 0**(`report_agent.py` 가 등급화 금지).
   우리에게 필요한 **정량 점수**는 어차피 우리가 다 만들어야 함.
3. **비용/지연 과다** — 수백 에이전트 × 10+ 라운드 × 행동마다 `qwen2.5:32b` 호출 = 아이디어 1건당 수천 호출.
   아이디어톤 다건 배치엔 부적합.
4. **운영/라이선스 부담** — Neo4j+Ollama+GPU(24GB VRAM) 상시 구동, **AGPL-3.0** 은 사내 독점 도구 내장에 리스크.

## 차용할 가치 (그리고 우리가 한 것)
- **합성 페르소나 패널** 개념(연령/직업/관심·편향 등 명시 특성) — 스택 없이 ~100줄 프롬프트로 구현 가능.
- → 본 레포 `ideathon_judge/market_sim.py` 로 **자체 경량 구현**:
  1. 타겟 유저에서 **다양성 축**(가격민감도·현재대안·회의성향 포함)으로 합성 페르소나 N명 생성
  2. **1회 구조화 LLM 호출**로 N명 반응(adopt/pay/WTP/excitement/objection/switching) 동시 산출
  3. Python 결정적 집계 → **수요 점수 0~100** + 분포 + 거부이유(설명가능성)
  4. 낮은 temperature·모델 고정으로 재현성, 캘리브레이션셋으로 보정
- 결과: 페르소나 현실성 + **방어가능한 수치**를, Neo4j/GPU/AGPL 없이 **아이디어당 단일 호출**로.

## 한 줄 권고
MiroFish 직접 도입 ✗. **개념만 차용한 자체 시장반응 스코어러**(이미 구현됨)가 비용·정량성·운영 모든 면에서 우월.
정교한 소셜 확산 시뮬이 별도로 필요해지면 그때 OASIS 를 **독립 실험 트랙**으로 분리 검토(심사 배치에는 비포함).
